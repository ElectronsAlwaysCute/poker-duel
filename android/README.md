## 2. 三种模式（启动选择；右上角 ⚙ 随时切换）

### ① 单机离线（默认）
APP 内置仅监听 `127.0.0.1` 的极简 HTTP 服务器提供内置资产；**完全离线**、无需电脑/网络；设置持久化、音频行为与桌面浏览器一致。

### ② 手机当房主（本机开联机服务器，无需 PC）
- 选择「手机当房主」后，APP 会在本机启动 **LAN 权威服务器**（HTTP + SSE，默认端口 5211，被占用则自动顺延 5212…）；
- 弹出对话框显示**加入地址**（例如 `http://192.168.1.23:5211`），可一键复制；
- **其他手机/电脑加入**：
  - 用浏览器直接打开该地址（普通网页版，无需装 APP）；或
  - 在另一台装了 APP 的手机上选「加入联机」，输入该地址（只填 `IP:端口` 即可）；
- 本机也会从 `127.0.0.1` 打开同一游戏页面，**房主自己也是玩家**：在页面的联机大厅创建房间，其他人加入即可开始；
- 房主 APP 退出/LAN 服务器停止后房间结束；需与加入设备处在**同一 Wi-Fi/局域网**（手机热点也可以，注意部分路由器「AP 隔离」会阻止设备互访）。

> 架构：Java 负责 HTTP 静态资源 + API + SSE 传输；游戏权威逻辑（房间/布阵/行动/镜像脱敏）由移植自 `server.js` 的纯 JS 权威 `lan_authority.js` 在**隐藏 WebView** 中运行，复用产品 `engine.js`；本机/其他客户端都只是普通浏览器客户端（与 PC 版 LAN 同协议）。

### ③ 加入联机（连接到 PC 或房主手机）
- 输入对方地址（PC 上 `start-lan.bat` 终端显示的 `http://192.168.x.x:5211`，或房主手机弹窗里的地址；只填 IP 由 APP 自动补 `:5211`）；
- 连接后进入联机大厅，创建/加入房间。

## 2.5 手机横屏 UI 重排与触屏输入（v2.11.1 / v2.11.2）

Android 手机横屏的 CSS 视口通常只有 ~380-470px 高，桌面版「顶部栏 + 双列侧栏 + 底部行动栏」会把手牌/牌桌挤到几乎不可用。v2.11.1 在**视口高度 ≤560px** 时启用专门的移动布局（桌面 1440×900 / 1280×800 完全不变）：

- **侧栏收起**：牌堆/决战阈值/比分/后手补偿/对局日志默认隐藏；顶栏新增「信息」按钮，点击打开右侧**抽屉**查看全部信息与日志，点「关闭 ✕」或按 Esc 收起（遮罩淡出）。
- **手牌移到最右侧竖列**：两列网格、可纵向滚动；区域牌桌占用腾出的全部宽度与高度。
- **压缩顶部栏/座位行/底部行动栏**：区域牌桌高度从原来的 ~45-60px 提升到 **~205px（740×360）/ ~235px（844×390）**；5 个区域可完整看到牌面与「可结算」徽标。
- 操作说明：选中手牌 → 点区域槽位；「信息」按钮随时查看被收起的信息。
- **v2.11.2 触屏修正**：① Android APP 内**禁用拖拽**（页面以 ?drag=0 加载；桌面浏览器仍可拖拽）——避免拖动与上下/左右滑动冲突，改用「点选手牌 → 点区域槽位」；② 打开「信息」抽屉时**不再压暗背景**（移除遮罩）。
- **v2.12.8 联机抖动/断流修复**：手机当房主的 Java SSE 服务在「JS 桥轮询超时」时错误返回 `closed:true`，导致服务端主动断开事件流 → 客户端反复重连，表现为游戏内网络很不稳定；同时 pending 表泄漏、140ms 轮询过密、未开 TCP_NODELAY。修复：轮询超时返回空事件（不关闭流）、超时清理 pending、单次轮询/JSON 异常最多连续 20 次才断流、心跳 5s、轮询 180ms、TCP_NODELAY。
- **v2.12.7 房间码长度修复**：手机当房主的权威 `lan_authority.js` 原先生成 **4 位**房间码，而客户端 UI/输入按 **5 位**校验（PC 版 `server.js` 的 ROOM_CODE_LEN=5）→ 手机建房显示 4 位码、对方无法正常加入。v2.12.7 已改为 **5 位**并与 PC 权威一致（authority 创建/加入测试通过）。
- **v2.12.6 离线兜底/联网权限提示**：① 部分国产 ROM 的安全中心「联网控制」会拦 App 的 127.0.0.1 回环访问，导致 WebView 报 `ERR_NETWORK_ACCESS_DENIED`；v2.12.6 自动回退到内置 `file://` 离线页面（已验证可正常加载游戏），并 Toast 提示到「手机管家/安全中心 → 联网控制」允许 App 联网；② 联机加载失败时错误提示区分「本机离线资源被拦」与「远端服务器不可达」；③ 保留 v2.12.5 的加入页网关探测 + 测试连接。
- **v2.12.5 联机地址探测/自检**：①「加入联机」自动读取当前 Wi-Fi/热点**默认网关**并自动填入 `<网关>:5211`（连热点时通常就是房主地址）；② 加入弹窗新增「**测试连接**」按钮（后台请求 `/api/info` 并提示可达/HTTP 码/失败原因，不关闭弹窗）；③ 房主页面在联机权威初始化超时也会打开大厅（可在大厅重试），不再空白；④ 房主说明明确「5 位房间码」；⑤ 继续修 **PC 当主机 + 手机加入**：PC 需运行 `start-lan.bat`/`node server.js`，并在 Windows 防火墙放行 TCP 5211（本机已给出命令）。
- **v2.12.4 房主联机 UX 修复**：① 房主/加入页面自动进入「联机大厅」（`?lan=1`），不再停在单机主菜单（用户反馈「点知道了后变成单机」）；② 房主页面在权威 JS 就绪后才加载，避免首屏 `/api/info` 失败；③ 房主地址列表追加常见热点网关（192.168.43.1 / 192.168.42.1 / 192.168.49.1 / 172.20.10.1 / 192.168.137.1）并提供「刷新地址」按钮（热点后开也能刷新）；④ 房主说明改为「创建房间 → 把 5 位房间码告诉对方」；⑤ 加入联机页面同样自动进入大厅，直接输入房间码加入。
- **v2.12.2 设置按钮归位**：按用户要求，把「返回/退出」从游戏设置面板移到右上角齿轮的「选择游戏模式」弹窗；设置面板恢复原样（仅局域网联机/取消/应用设置/开始对局）。
- **v2.12.1 联机修复**：房主服务器（HostServer）此前缺少 **POST /api/rooms 创建房间路由** → 房主创建房间收到 404、客人因房间不存在无法加入，双方都卡在自己的界面。v2.12.1 已补该路由，并用 Node HTTP/SSE 仿真 + 双客户端 E2E 验证「创建→加入→SSE→双方布阵→进入战役→行动→对端收到更新」全链路 PASS。
- **v2.11.3 弹层/设置适配**：① **单独结算、终局胜利、设置、规则、确认弹层**全部按视口高度 ≤560px 紧凑化（弹层宽度/字号/牌面/按钮/内边距缩小，740×360 下结算弹层 560×210、终局弹层 620px 宽可完整显示按钮）；② **「返回」「退出」放在右上角齿轮「选择游戏模式」弹窗**（返回=关闭弹窗、保持当前模式/对局；首次启动未选模式时返回=进入单机；退出=关闭 APP）；**设置面板内不再有 Android 专属按钮**（v2.12.2 按用户要求取消）。

> 实测视口：1440×900、1280×800（桌面对照，未变）、1000×470、960×440、900×420、844×390、740×360（手机横屏档）；截图见 `art/qa-mobile-probe-*`。

## 4. 构建（可复现）

环境（本机已装好）：JDK 17 便携版 `tools/tmp-v28/android-pack/jdk17`；Android SDK `platform-tools / platforms;android-34 / build-tools;34.0.0`（默认 `%LOCALAPPDATA%\Android\Sdk`）。

```powershell
cd D:\GAME\poker-duel
powershell.exe -NoProfile -ExecutionPolicy Bypass -File android\build.ps1
```

流程：复制游戏资产（只读）+ host-overlay（`android/host-overlay/` → `assets/host/`）→ 生成图标 → aapt2 compile/link → javac（MainActivity + HostServer + HostAuthority）→ d8 → 写入 `classes.dex` + `assets/`（正斜杠路径）→ zipalign → apksigner → 校验 + SHA-256。

- 为什么不用 Gradle：build-tools 手工组装即可，无需 Gradle/AGP；脚本已修复 Windows 上 `aapt2 -A` 资产反斜杠路径问题（会导致 WebView 404）。
- 联机权威 JS 逻辑有 Node 单测：`node tools/tmp-v28/android-host/test-authority.js`（用真实 engine 模拟两名客户端走完创建/加入/布阵/行动/终局/再来一局/离开，含镜像视角与信息脱敏断言，全部 PASS）。

## 5. 已知限制 / 真机验证清单

本构建机**没有安卓设备、未安装模拟器**：APK 已做静态校验（manifest/assets/dex/签名）与权威 JS 的 Node 全流程测试，但 **Java HTTP/SSE 服务器、隐藏 WebView 桥接、触屏交互未真机实测**。拿到手机后请验证：

1. [ ] 安装、启动、模式选择；
2. [ ] 单机：完成一局（布局→战役→战略决战→终局）；设置持久化；音频；横屏/常亮；返回键；
3. [ ] **手机当房主**：启动后弹窗显示地址；本机页面能建房；
4. [ ] 另一台手机（APP 加入）或电脑浏览器打开房主地址 → 加入房间 → 双方布局/行动同步、终局一致；
5. [ ] 两台手机同时加入房主手机 → 可对战；房主退出后房间结束；
6. [ ] 触屏拖动：背面牌同区拖动=翻牌、异区拖动=移牌；小屏文字/牌面大小可接受。

已知限制：
- 联机需同一局域网；部分路由器 AP 隔离/防火墙会阻止互访（可改用手机热点，由房主手机开热点、对方连热点）；
- 明文 HTTP（局域网常见做法），建议仅在可信局域网使用；
- 横屏锁定、竖屏未适配；
- 房主模式服务器随 APP 进程存活（切后台通常仍在，系统回收/退出即停止）；
- 自签证书：不同签名 APK 不能覆盖安装，需先卸载；安装时需允许未知来源。
