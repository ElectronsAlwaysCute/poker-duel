# UI 规格（视觉 / 交互 / 文案）

> 实现目标：单机网页游戏「扑克牌 · 比大小」，中文界面，无外部依赖，`file://` 直接打开可玩。
> 契约字段见 `docs/CONTRACT.md`，规则见 `docs/RULES.md`。

## 1. 视觉基调

- 主题：暗色高级牌桌 —— 墨绿绒面 + 金色描边 + 羊皮纸卡片，带轻微赌博电影质感（纯娱乐、无真实货币元素）。
- 色板（CSS 变量建议）：
  - `--felt-0:#071f18; --felt-1:#0b3327; --felt-2:#14503c;` 桌面渐变
  - `--gold:#d9b45b; --gold-soft:#f0d79a; --ink:#e9e4d6;`
  - `--red:#d9534f; --win:#5fc98a; --lose:#e0605e; --tie:#b9a97a;`
  - `--card-bg:#f7f1e3; --card-ink:#1d1a14;`
- 字体：`"Microsoft YaHei","PingFang SC","Noto Sans SC",system-ui,sans-serif`；数字/牌面可用 `Georgia,"Times New Roman",serif` 提升质感。
- 圆角、轻阴影、金色细线；禁止使用外链图片/字体/音效资源。
- 支持 `prefers-reduced-motion`：关闭大幅动画。

## 2. 页面结构（1440×900 基准）

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 标题：扑克牌 · 比大小        [战前布局 → 战役消耗 → 战略决战 步骤条]   ⏱30s 🔊 ♪ ⚙ 规则 │
├───────────────────────────────────────────────┬───────────────────────────┤
│ 对手区：名字 · 手牌(背面堆叠 n) · 区域胜场 平局 │  对局日志                 │
│                                               │  （滚动，最新在底部）      │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ...      │                           │
│  │ 区域 1  │ │ 区域 2  │ │ 区域 3  │ 5 列      │  ┌─────────────────────┐  │
│  │对手正面牌│ │ ...     │ │         │          │  │ 牌堆 33             │  │
│  │  VS 差值 │ │         │ │         │          │  │ 决战阈值 10         │  │
│  │我方正面牌│ │         │ │         │          │  │ 比分 你 1:0 电脑     │  │
│  │背面牌数  │ │         │ │         │          │  └─────────────────────┘  │
│  └─────────┘ └─────────┘ └─────────┘          │                           │
├───────────────────────────────────────────────┴───────────────────────────┤
│ 我方区：名字 · 手牌（扇形/横排，可点击）                                      │
├───────────────────────────────────────────────────────────────────────────┤
│ 行动栏：[1 结算] [2 翻牌] [3 放牌] [4 移牌] [5 摸牌]      提示文字/回合指示   │
└───────────────────────────────────────────────────────────────────────────┘
```

- 桌面最小适配 1280×800；宽度 `<1200` 时整体缩放卡片尺寸，布局不换行、不出现横向滚动条。
- 区域数量 3/5/7 自适应等宽列。
- 结算后的区域列不消失：变成「已结算结果卡」，显示 胜/负/平、双方最终总和、结算补牌，并置灰。

## 3. 区域列组件

每个未结算区域从上到下：
1. 标题 `区域 N` + 状态徽标（`可结算` 高亮 / `已结算`）。
2. 对手正面牌横排（小牌，44×62px），右侧显示 `对手总和` chip；牌多时该行最多显示 2 行，超出纵向滚动（v2.4，细金色滚动条，全部可查看）。
3. 中间 VS 条：`差值 +3`（我方-对手，颜色区分）或 `持平`。
4. 我方正面牌横排 + `我方总和` chip；溢出规则同上（v2.4 纵向滚动）。
5. 双方背面牌：对方/我方各占一整行（`.back-group`：标签 + 单行横向滚动牌堆 `.back-stack`，v2.4）；我方背面牌为**半透明暗牌**（真实 rank/suit + 虚线边，仅自己可见，可点击/拖拽；v2.5 移除「暗」角标），对手仅显示牌背；牌多时可横向滚动查看。
6. 状态样式：可结算区域金色呼吸边框；当前选中目标区域高亮描边 + 抬升。

结算后：显示 `胜/负/平` 大字横幅、双方最终总和（含补牌明细，如 `♠K + ♥7 = 20`）、难度摸牌信息；内容/结果牌列表溢出时区域纵向滚动可查看（v2.4）。

## 4. 各阶段交互

### 4.1 设置 / 开始（首次进入或点 ⚙）
全屏暗色遮罩 + 居中面板（宽 720）：
- 标题「开始新对局」，副标题规则一句话。
- 难度（容错率，仅影响单独结算后谁摸牌；v1.4 标题改名）：三选一卡片：
  - 消耗：单独结算后**败者**摸牌（容错率最高）
  - 均衡：单独结算后不摸牌
  - 突进：单独结算后**胜者**摸牌（容错率最低）
- **结算随机性**（v1.2 引入，v1.3 复杂档改为 4 张）：三选一卡片
  - **简单**：单独结算双方各补 **1** 张（波动最小；单次结算消耗 2 张、决战阈值只降 2，牌堆差距不会缩小，决战通常来得最晚）
  - **标准**：双方各补 **2** 张（默认；单次消耗 4 张、差距缩小 2，R=5 时初始差距 22 张，约 11 次结算进入决战）
  - **复杂**：双方各补 **4** 张（波动最大；单次消耗 8 张、差距缩小 6，R=5 时约 4 次结算就进入决战，7 区几乎每局都会决战）
  - 每档标注「单次结算双方各补 N 张 · 每结算一次与决战阈值的差距缩小 2N−2 张」；牌堆固定标准 54 张（不再提供牌堆构成设置）。
  - 3 / 5 / 7 区域均开放三档（54 张在 7 区下仍满足布局后牌堆 > 初始阈值）；仅提示 7 区 + 复杂会较早进入决战（规则后果，不禁止）。
- 区域数：3 / 5 / 7（默认 5，即「5 局 3 胜」）。
- 先手：随机 / 我先手 / 电脑先手（默认随机）；后手补偿 = **固定 1 张**（v2.1；3/5/7 区相同）。
- 电脑强度（v1.2 三档）：简单 / 中等 / 困难；默认中等。困难＝近最优 AI（精确结算概率、提前锁定与难度收益评估、结算回合成本、手牌总和决胜），仅带极小幅随机扰动；简单档会明显失误。v2.2 起中等/困难 AI 会在决战与战役中使用移牌（集中背面牌、主动放弃赢不了的区域）。
- 电脑强度（三档，默认中等）：
  - **简单**：稳健启发式（评估结算胜率与区域价值、会移牌，随机性小）。
  - **中等（默认）**：最强启发式（整回合计划搜索、锁定价值、决战连续放牌）。
  - **困难**：机器学习（`js/ai-ml.js`，PokerAIML **v2.2.0**：6 世界模型 ensemble + planpi K=4 + 决战 build 自适应搜索（首行动 beam8/budget200、同回合后续 beam6/budget120）+ **place→end_turn 放牌节奏候选**，含学习驱动的主动空过候选；全区域 3/5/7 启用；ML 不可用/异常时自动回退中等档同款最强启发式）。
  - 设置面板**不再提供「AI 引擎」二选一**（无 `ai-engine-*` / `ai-engine-hint` / `settings-ai-engine` 节点）；困难档即机器学习，回退自动进行。
- 动画：标准 / 快速（关闭大部分动画）。
- **回合倒计时（v1.5 新增）**：`关闭 / 15 秒 / 30 秒（默认）/ 60 秒` 四选一（`timer-option-0|15|30|60`，`data-setting="turnTimeLimit"`），说明「每回合限时，超时自动结束回合」；提示文字 `timer-hint` 显示当前值。单机与 LAN 建房都会带上该配置；默认 30 秒。
- **背景音乐（v1.4 新增）**：设置面板「背景音乐」区块：开 / 关 两个单选（`music-enabled-0/1`）+ 音量滑杆 0–100（`music-volume`，默认 30%，0=静音，拖动即时试听并显示百分比 `music-volume-val`；1280 下与「动画」并排两列无需滚动）。顶栏另提供 ♪ 快捷开关（`btn-music-toggle`，静音置灰、title 显示当前音量、点击保存并提示）。背景音乐为本地 `music/1.mp3` 循环播放；受浏览器自动播放策略限制，首次点击/按键/触摸后开始播放，播放失败静默不影响游戏。
- **音效（v1.5 新增）**：设置面板「音效」区块：开 / 关（`sfx-enabled-0/1`）+ 音量滑杆 0–100（`sfx-volume`，默认 **70%**，拖动即时试听并显示百分比 `sfx-volume-val`）；顶栏 🔊 快捷开关 `btn-sfx-toggle`（aria-pressed）。音效为本地 `sfx/*.ogg`（Kenney CC0，已做响度均衡：目标 -20dBFS、峰值 ≤ -1dBFS），与背景音乐独立音量；首次用户手势解锁，关闭/失败静默不影响游戏。
- 提示条：`结算随机性「标准」· 区域 5 · 3 胜制 · 牌堆 54 张 · 后手补偿 1 张 · 回合倒计时 30 秒 · 预计额外消耗约 23 张后进入战略决战（决战阈值 20）`（来自 validateConfig().info）。
- 按钮：`开始对局`（主）、`局域网联机`（次）、`取消`、`应用设置`；从终局面板打开时标题为「对局设置」。
- 设置持久化到 localStorage（含 aiStrength、settleCards、turnTimeLimit、sfxEnabled/sfxVolume；旧设置中的 deck 字段忽略/归一化为标准 54；旧 aiStrength:'normal' 迁移为 medium）。

> 弹层层级（BUG 修复）：设置/规则弹层必须位于终局面板之上（z-index 52，终局 50、结算确认 55、LAN 58+），保证「调整设置」「查看规则」可点击。

### 4.2 战前布局
- 顶部横幅：「战前布局 · 从 10 张手牌中选出 5 张，**背面朝上**放入 5 个区域；双方放完后同时翻面」；显示你是**先手/后手**（后手额外补偿固定 1 张：v2.1，3/5/7 区相同）。
- 中部 5 个区域槽位（空槽显示金色虚线框「放置区域 N」）。可点击已放置区域取回该牌。
- **放置后的牌在槽位中一律显示为牌背**（我方也是），揭示前不显示正面；已使用的手牌可在手牌区以缩小正面 + 区域角标辅助玩家记忆（玩家自己的信息）。
- 底部 10 张手牌；点选卡片（金色描边、上浮）→ 点区域槽位放置；已放置的手牌在手牌区置灰并显示所在区域角标。
- **拖动支持（v1.5）**：直接从手牌按住拖到区域槽位即可放置（Pointer Events，移动 >6px 才算拖拽，避免与点击冲突）；拖动时显示跟随光标的 `drag-ghost`，合法槽位高亮 `is-drop-hover`；把已放置槽位的牌拖回手牌区 = 取回；非法落点松手取消并 `ui.error` 提示；触屏同样可用。
- **放牌动画（v1.2 强化）**：点击手牌→槽位时，以 ghost/FLIP 方式让牌从手牌位置飞向槽位并落位为牌背（200–300ms）；电脑布阵完成时同样以牌背落入动画展示；动画不得提前泄露正面。
- 底部按钮：`清空重选`、`确认布阵 (3/5)`（未满 5 不可点）。
- 确认后：播放「双方揭示」动画——先保持所有牌背短暂停顿（约 0.5–0.6s）→ 双方 5 张牌背**同时**逐区翻到正面（同一区域的我方与电脑牌一起翻，不能先翻一方；每区间隔约 90ms，3D 翻面）；若你是后手，播放 **1 张**补牌动画（牌从牌堆飞入手牌；电脑为后手时其牌背/只显示张数，不泄露牌面）；然后进入战役阶段。
- 揭示+补偿后的初始手牌：先手 `R` 张、后手 `R + 1` 张（5 区 = 5 / 6 张；7 区 = 7 / 8 张）
- 对手布局在选择期间显示为背面牌占位（数量 = 区域数）。

### 4.3 战役阶段（v1.4：行动点 + 一回合多行动 + 结束回合）
- **回合倒计时（v1.5）**：顶部行动区显示 `[data-testid="turn-timer"]`（整秒数字「30s」+ 细进度条，`data-total`/`data-remaining`/`data-state="idle|running|paused|expired|off|opponent"`）；剩余 ≤10s 红色 `.is-urgent`、≤5s 脉冲 `.is-critical` 且每秒播放一次提示音；归零 toast「⏱ 超时，自动结束回合」并自动执行结束回合。对手回合显示「对方行动中」小胶囊；布局/终局/关闭时隐藏。设置/规则/确认弹层打开、页面不可见时暂停。仅本地玩家回合计时；新回合重置、同回合多行动不重置。超时也累计 `stallCount`（连续两次超时会认输）。
- **拖动支持（v1.5，v1.6 落点分流增强）**：手牌拖到未结算区域 = 放牌（place，1 AP）；我方区域**背面牌拖回所在区域 = 翻开（flip，2 AP）**、**拖到其他开放区域 = 移牌（move，1 AP）**。落点动作统一由 `E.getLegalActions(state)` 判定（不写死规则，决战 build 阶段同样走引擎合法性），合法才经既有 `commitAction` 管线提交；拖拽期间不触发点击选择。
  - **悬停提示（v1.6）**：悬停区域加 `is-drop-hover`，并按落点动作追加 `is-drop-flip` / `is-drop-move` / `is-drop-place`、合法 `is-drop-valid` / 非法 `is-drop-invalid`（非法为红虚线描边）；区域元素写 `data-drop-action="flip|move|place"`、`data-drop-valid="true|false"`，并在区域内插入动作徽标 `[data-testid="drop-action-badge"]`（随徽标也带 `data-drop-action`/`data-drop-valid`）——合法显示 `翻开 · 2 AP` / `移牌 · 1 AP` / `放牌 · 1 AP`，非法显示暗红不可用样式与原因（如 `翻牌需要 2 点行动点（当前 1 点）`、`目标区域已结算，无法移牌`、`战略决战最终结算中，暂不可操作`）。
  - **非法落点（v1.6）**：AP 不足 / 区域已结算 / 决战最终结算等情况下松手**不改变任何状态**，播放 `ui.error` 并 toast 明确原因（同区 flip 提示翻牌所需 AP、异区 move 提示目标不合法原因）。
  - **拖拽视觉（v1.6）**：源牌加 `.is-drag-source` 压暗；ghost 带 `data-drag-kind`（hand/back/slot），未悬停区域时 `[data-testid="drag-ghost-action"]` 显示默认映射（`拖回本区域 = 翻开 · 其他区域 = 移牌`），悬停区域后由区域动作徽标接管提示。`Esc` / pointercancel 取消；busy / 非本人回合 / 动画期间不可拖；触屏 pointer 同样可用。
- **防拖延/认输提示（v1.5）**：本回合无有效行动或仅移牌会累计 `stallCount`（公开）；本地玩家 `stallCount=1` 时 toast 警告「再空过一回合或仅移牌将判负（认输）」；终局面板在 `result.reason='forfeit'` 时显示「认输（连续两回合无有效行动/仅移牌）」，不把区域胜场当作胜因展示。
- **行动点显示**：行动栏上方/侧边显示当前回合行动点 `AP ●●●`（`[data-testid="action-points"]`，文本如「行动点 2 / 3」，另加 `data-ap="2"`），每回合开始回满 3 点。
- 行动栏 5 个行动按钮 + 1 个「结束回合」按钮，含图标/数字快捷键/一句话说明（tooltip + 按钮下小字）与**消耗角标**（结算 3 · 摸牌/翻牌 2 · 移牌/放牌 1 · 结束回合 0）：
  1. 结算 — 令任意未结算区域立即结算（v1.4 不再要求正面牌 >2；消耗 3 点，通常一整回合）
  2. 翻牌 — 翻开一张我方背面牌（2 点）
  3. 放牌 — 手牌背面朝上放入区域（1 点）
  4. 移牌 — 移动我方一张背面牌到其他区域（1 点）
  5. 摸牌 — 从牌堆摸一张（2 点）
  6. 结束回合 — 提前结束本回合，放弃剩余行动点（0 点；`[data-testid="btn-end-turn"]`，快捷键 `Space`）
- 按钮不可用（AP 不足/无目标/阶段禁用）时禁用，并给出原因 tooltip（例如「行动点不足（需要 2 点）」「决战阶段摸牌已禁用」）。
- 一回合内可连续执行多个行动：每次行动后刷新 AP 显示与按钮可用性；AP 耗尽或无可用行动时自动结束回合，否则玩家可继续操作或点「结束回合」。
- 点击行动按钮进入「选择目标」模式：
  - 顶部提示文字变化，例如「请选择要结算的区域（Esc 取消）」；合法目标高亮、非法目标变暗。
  - 结算：点合法区域（任意未结算区域）→ 弹出结算确认框（显示双方当前总和、提示「结算后该区域废弃」）→ 确认执行 / 取消。
  - 翻牌：高亮我方背面牌（区域内的可点小牌背）→ 点击直接执行。
  - 放牌：先点击手牌，再点击合法区域；或先点区域再点手牌（任一顺序均可）。
  - 移牌：先点我方背面牌 → 再点目标区域。
  - 摸牌：直接执行。
  - Esc / 右键 / 再次点击同一按钮 = 取消选择。
- **己方背面牌悬停信息（v1.4）**：鼠标悬停在我方区域内的背面牌上时，显示该牌的真实牌面信息（tooltip/浮层，如「♠K（13）」，`[data-testid="own-back-tooltip"]`）；仅自己可见，对手背面牌不显示；触屏/键盘聚焦时也应可查看（title/aria-label）。
- 电脑回合：显示「电脑思考中…」三点动画，所有玩家操作禁用；电脑一回合内可能连续行动多次，行动后日志追加、动画播放；直到其回合结束才交回玩家。
- 每次行动后：更新 AP、牌堆计数（危险时红色脉冲）、比分、区域状态；若触发决战 → 播放决战序列。

### 4.4 单独结算动画（v1.2 改为分段补牌动画，可点击跳过）
居中卡片浮层（`settlement-overlay`，`data-anim-state` 依次为 `drawing → revealing → result`）：
- 标题 `区域 N 结算`，副标题 `双方各补 N 张牌后比较总和`（N=结算随机性）。
- 补牌阶段（drawing）：显示双方结算前正面牌与当前总和；牌堆图标 → 双方牌列依次各飞入 N 张牌背（每张 120–180ms），我方与对方交错展示。
- 翻开阶段（revealing）：补牌逐张 3D 翻到正面，双方合计数字从旧值滚动增加至最终值（约 300–450ms），短暂停顿制造悬念。
- 结果阶段（result）：结果横幅 `你赢得此区域`（绿）/ `电脑赢得此区域`（红）/ `平局`（黄）盖章弹入；展示难度摸牌提示（`难度：败者摸牌 → 电脑摸 1 张`）。
- 底部「继续」（自动继续；单独结算约 2.2–2.6s，决战约 1.4s），点击/空格可跳过至结果。
- 动画只用 transform/opacity；禁止 backdrop-filter；快速动画模式下直接展示结果。

### 4.5 战略决战（v1.3 重构：补牌 → 构筑 → 摊牌）
- **触发**（牌堆 ≤ 2 × 剩余区域数 X）：全屏金色闪光 + 大字「战略决战」+ 副标题「牌堆仅剩 N 张，剩余 X 个区域将直接按点数之和结算」（1.2s）。
- **决战补牌**（`endgame-draw-p1/p2`）：双方各把 X 张牌从牌堆摸入手牌，牌堆被摸空（不足时 P1 = ⌊剩余/2⌋、P2 = 剩余）。逐张飞入动画 + 计数。
- **决战构筑阶段**（`endgame-build-banner`，`data-phase="build"`）：显示横幅「决战阶段 · 仅可翻牌/放牌/移牌（摸牌与结算已禁用）」；行动栏禁用「结算」「摸牌」；行动点规则同样生效（每回合回复 3 点，翻牌 2 / 放牌·移牌 1 / 结束回合 0），一回合可连续行动；轮流出牌，牌堆已空。
- **自动跳过**：某方手牌为 0 且己方区域内无背面牌（无牌可翻/可放/可移）时，自动跳过其回合（`endgame-skip-notice`：「<玩家> 无牌可用，跳过回合」），每方最多提示一次。
- **摊牌**（`endgame-showdown-banner`）：双方都无牌可用 → 播放「摊牌」动画。
- **确定性结算**：按区域序逐区结算（`settlement-overlay[data-deterministic="1"]`，不再补牌、无随机性，直接比较双方正面点数之和；每区约 0.9s，可加速）。
- **提前锁定（v1.2 起）**：逐区结算途中若一方区域胜场达到胜场门槛，立即停止剩余区域结算并弹出终局面板；剩余区域显示「未结算」。
- 全部区域结算完 → 终局面板。
- 动画关闭/快速模式下直接展示补牌与结果，`PokerDebug` 状态可立即读取。

### 4.6 终局面板
- 大字结果：`你获胜 / 电脑获胜 / 平局`（配金色/红色/灰色调）。
- 获胜原因（v2.6 BUGFIX）：`区域胜利 3 : 1`（提前锁定）/ `区域胜场 3 : 2，胜场多者获胜 · 平 2`（无人达门槛、胜场不同，**不再误判平局**）/ `区域胜场相同（2 : 2 · 平 1），比较手牌总和 37 : 35`（hand_sum）/ `区域胜场与手牌总和均相同（区域 2 : 2 · 平 1，手牌总和 0 : 0）`（真平局；只有两者都相同才可写「均相同」）。
- **提前锁定（v1.2）**：结果区显示「提前锁定」徽标/标签与说明「已取得 3 个区域胜利，剩余 2 个区域未结算」；未结算区域在结果小卡中显示 `未结算`（不得伪装成平局）；手牌总和对比仅作记录、不高亮。
- 5 个区域结果小卡（胜/负/平 + 双方总和；未结算则灰显`未结算`）。
- 双方手牌总和对比条（仅 `reason='hand_sum'` 手牌总和决胜时高亮；提前锁定/认输/`region_wins`/平局仅展示）。
- 页脚显示 `共 N 个战役行动 · 结算随机性「标准」`（单机带种子，联机带房间码）。
- 按钮：`再来一局`（同设置新种子）、`调整设置`、`查看规则`。
- 联机模式下：「再来一局」需双方确认（显示 `<对手名> 已准备/等待对方…`）；增加 `离开房间`。

### 4.7 局域网联机（v1.1）
- **模式选择**：开始页/设置页提供 `单机对战` 与 `局域网联机` 两个入口；仅当 `GET /api/info` 可用时联机入口可点，否则提示「请先运行 node server.js 启动局域网服务器」（附命令，可复制）。
- **联机大厅**（模态，深色牌桌风格）：
  - 昵称输入（默认 `玩家` + 随机 3 位，≤16 字）。
  - 创建房间：显示对局设置摘要（难度 / 结算随机性 / 区域数 / 先手 / 牌堆 54）→ `创建房间`；创建后切换为**等待房间**。
  - 加入房间：5 位房间码输入（自动大写）；支持 `?room=CODE` 预填并提示「加入房间」；`加入房间`。
  - 错误提示：房间不存在/已满/服务器不可用/昵称非法。
- **等待房间**：大号房间码（可点击复制）、局域网地址（可复制，优先非 127.0.0.1 地址）、`等待对手加入…` 动画、`取消建房`；guest 加入后自动进入布局。

- **再来一局**：终局面板按钮变为「再来一局（双方确认）」；单方点击后显示「已准备，等待对手…」，双方都准备后自动开新局。
- 所有玩家名（座位/比分/日志/区域结果/提示）统一使用 `state.config.playerNames`；**不得硬编码「你/电脑」**（单机下 playerNames 仍为 你/电脑，显示不变）。玩家自己一侧仍显示 `你` 徽标或高亮区分。

### 4.8 托管（v1.6 单机，v1.7 支持联机对局）
- **入口**：顶栏 `[data-testid="btn-autoplay"]`（文案「托管」↔「取消托管」，`aria-pressed`，开启时金色实心 `.is-active`）；在**单机与联机对局**的布局/战役阶段显示；LAN 大厅/等待房间（无对局）、`?autoplay=1` 自动演示、终局时隐藏。游戏中可随时开/关。
- **行为（单机）**：开启后本地玩家由**简单 AI（easy）**代打——布局阶段自动 `chooseLayout` 并提交/揭示（双方同时揭示）；战役与战略决战 build 阶段在轮到本地玩家时自动 `chooseAction` 并通过既有 `commitAction` 管线提交（行动/AP/动画规则与手动完全一致，节奏受动画速度设置影响）；对手回合仍由原 AI 调度，不重复排程。终局/再来一局自动复位关闭；每局默认关闭、不写入 localStorage。
- **行为（联机 v1.7）**：布局阶段用 easy `chooseLayout` 选牌后走既有 `confirmLanLayout` → `net.submitLayout` 网络提交（不触碰单机本地 finalize 路径），等待服务器 SSE 揭示；战役/决战 build 在自己回合用 easy `chooseAction` → 既有 `commitAction` → `commitLanAction` 网络提交，**等服务器 SSE 更新落地并渲染完成后再决策下一步**（`actionPending`/`processing` 期间暂停，防重复提交）；对手回合只看不代打。对手掉线/重连中托管自动暂停并 toast「对手已断开，托管已暂停，等待重连…」，重连恢复后 toast「对手已重连，托管继续」；联机终局、再来一局新局、离开房间、断线回单机、进入新房间时托管自动关闭/复位。
- **UI 状态**：托管期间顶部显示横幅 `[data-testid="autoplay-banner"]`（`data-phase="layout|battle"`、`data-ai-strength="easy"`、`data-mode="solo|lan"`；单机文本「托管中（简单 AI）· 自动布阵中/代打中 · 点顶栏「取消托管」接管」，联机文本「托管中（简单 AI）· 联机自动布阵中/联机代打中 · …」）；本地操作入口（行动按钮 / 手牌 / 区域背面牌 / 布局槽位 / 确认布阵）置灰（`body.is-trustee`），且逻辑层忽略点击、拖拽与快捷键；取消托管后立即恢复。
- **与计时器**：托管期间（单机与联机）本地回合倒计时暂停，顶部计时胶囊显示「托管中 · 简单 AI」（`turn-timer[data-state="trustee"]`，不跑秒），避免超时自动 `end_turn` 与托管竞争；取消托管后恢复计时（重新给满当前设置时限）。设置/规则/确认弹层打开或页面切到后台时托管调度暂停，关闭/回前台后自动继续。
- **安全退出**：AI 无合法行动 / 执行异常 / 连续提交失败 / 等待超时（动画、网络、对手调度异常）时自动取消托管并 toast 提示，不留半状态。
- **调试接口**：`PokerDebug.setAutoplay(bool)` 开/关托管并返回状态（单机与联机均可用）；`PokerDebug.autoplayState()` 返回 `{enabled,active,aiStrength:'easy',phase,turn,busy,pending,paused,pauseReason,lan,banner,button}`，其中 `pauseReason` 取值 `''|'opponent-offline'|'waiting-server'|'waiting-reveal'|'not-local-turn'|'rendering'`。

### 4.9 联机零命令体验（v1.7）
- **目标**：用户不需要手动敲 `node server.js`。项目提供双击即用的「启动联机.bat」（内部 `node tools/launch.js`：启动本地联机服务器并自动打开浏览器进入 `?lan=1` 联机大厅）。前端负责「自动探测 + 自动跳转 + 未启动时的一键启动引导」。
- **点击「局域网联机」的行为**（设置页 `[data-testid="btn-lan-mode"]`）：
  - 页面本身由本地服务器通过 **http(s)** 提供 → 保持现状，直接打开联机大厅（`lan-lobby`）。
  - 页面为 **file://** 且本地服务器已在运行 → 用 `fetch(mode:'no-cors')` 探测 `http://127.0.0.1:<port>/`，成功则记录端口并**自动跳转** `http://127.0.0.1:<port>/?lan=1`，toast「已连接本地联机服务器（端口 N），正在进入联机大厅…」。
  - 页面为 **file://** 且服务器未运行 → 打开**一键启动引导**弹层 `[data-testid="lan-launch-guide"]`（overlay 上带 `data-state="probing|found|not-found"`）：
    - 标题「启动局域网联机」；分步说明：①双击项目目录里的「启动联机.bat」（自动启动服务器并打开大厅，无需命令）②回到本页点「我已启动，重试」。
    - 状态区 `[data-testid="lan-launch-status"]`：探测中（spinner + 正在探测本地联机服务器… + 尝试端口列表 `[data-testid="lan-launch-ports"]`）→ 未检测到（红色提示 + 已尝试端口 + 下一步说明）→ 已连接（绿色，随后自动跳转）。
    - 命令兜底：`[data-testid="lan-launch-command"]` 显示 `node tools/launch.js` + 「复制启动命令」按钮 `[data-testid="lan-copy-command"]`（复制成功 toast「已复制：node tools/launch.js」）。
    - 「我已启动，重试」`[data-testid="lan-retry-connect"]`：重新探测（探测中禁用）；「返回单机」`[data-testid="btn-lan-launch-close"]` / Esc / × 关闭引导并回到设置页；失败不阻塞单机、不报错（Node 是否可装无法从浏览器判断，只给引导）。
  - 探测端口顺序：localStorage 上次成功端口优先，其次 `5200`、`5211`（`LAN_PROBE_PORTS`），单次探测超时 1.5s，并行探测后按顺序取首个可达端口。
- **记录上次成功端口**：localStorage 键 `poker-duel-lan-port`（如 `5200`）。HTTP 页面进入联机大厅且服务器可用时记录当前端口；file:// 再次点击入口时优先探测该端口。不写入 CONTRACT 设置契约。
- **服务端地址展示**：联机大厅/等待房间沿用现有地址展示（`lan-share-url`、局域网地址复制）；大厅离线提示文案更新为优先引导双击「启动联机.bat」/ 运行 `node tools/launch.js`。
- **兼容性**：file:// 单机游玩完全不受影响（不点联机入口不发起任何探测）；HTTP 页面原有联机流程零回归；通过服务器打开的页面中 LAN 托管（§4.8）可用。

## 6. 动画与节奏

- 发牌/摸牌：牌从牌堆位置飞向目标（transform + opacity，200–300ms）。
- 布局放牌：手牌 → 槽位的 ghost/FLIP 飞入 + 落位牌背（约 260ms）；揭示前保持背面。
- 翻牌：3D `rotateY` 200ms；布局揭示逐区 90ms 错峰同时翻开。
- 结算补牌（v1.2 重点）：双方各 N 张牌从牌堆依次飞入牌列（每张约 120–180ms）→ 逐张翻面 → 合计数字滚动 → 结果盖章；点击/空格可跳过。
- 区域高亮：金色呼吸 box-shadow。
- 结算浮层：淡入 + 上浮 180ms；结果横幅 scale 弹入。
- 决战：全屏闪光 + 轻微镜头推进（scale 1.0→1.02）；补牌/摊牌序列节奏见 §4.5。
- 动画关闭模式下：所有过渡 0ms，结算/决战直接展示结果，`PokerDebug.dispatch` 后立即可读最终状态；busy 锁不得因动画关闭而卡死。
- 仅使用 transform/opacity（禁止 backdrop-filter 等重合成效果）。
