# 规则风险分析：`draw`（摸牌）无上限 → 「摸牌囤牌 → 拖入决战」利用策略

> 来源：v2.9 纯学习 battle 学习头（零注入原型，`tools/tmp-v28/pure2/`）在优化胜率时自发学到「只摸牌/结束回合，把牌堆摸到决战，再靠手牌优势打决战」的利用策略；ml-dev 已定位到引擎规则，qa-v6 已知悉。**本文件只做分析，不改产品；是否改规则由用户（设计者）决定。**

## 1. 现行规则（证据：`docs/RULES.md` / `js/engine.js` 1.6.0）

| 项 | 现行规则 | 出处 |
|---|---|---|
| 摸牌合法条件 | 战役阶段牌堆张数 > 决战阈值即恒可摸牌（**每回合次数无上限、全局无上限**） | RULES §6/§11（"手牌上限/行动次数上限：无"）；engine 行动合法性 |
| 摸牌成本 | **2 AP**（每回合 3 AP，不结转） | RULES §5.1 / engine ACTION_COSTS |
| 决战触发 | 任意行动后 `牌堆剩余 ≤ 2 × 未结算区域数` → 立即进入决战；决战时双方各摸「剩余区域数 X」张 | RULES §6.2/§8 |
| 决战阶段 | 禁用摸牌/结算，只能翻牌(2)/放牌(1)/移牌(1)，每回合 3 AP，可提前结束 | RULES §6.4 |
| 摊牌平局 | 区域胜场相同 → 比较**手牌点数总和** | RULES §9 |
| 防拖延 | 连续 2 个「无产出回合/只有 move」→ 认输；摸牌属于产出行动，**囤牌不会触发 stall 判负** | RULES §5.1 #33/#34 |

## 2. 为什么可被利用

1. 摸一张牌 = 2 AP，产出行动（stall 清零），且牌堆 −1 → 更快触发决战；
2. 决战触发时双方各再摸 X 张（X=剩余区域数），**手牌在决战=可放置资源 + 摊牌平局的手牌总和比较值**；
3. 因此「用 2 AP 换 1 张手牌、并把对局推进到决战」在数学上等价于「把战役阶段剩余行动点存成手牌进入决战」——当对手按正常节奏结算/翻牌时，囤牌方在决战拥有人数级手牌优势；
4. 唯一制衡是「对手可以在你囤牌期间结算区域、提前锁定获胜（early lock）」，但取决于配置（R3 需要 2 胜、R5 需要 3 胜、R7 需要 4 胜）与牌堆/结算速度——**7 区 4 张难度 1 下尤其容易拖**。

## 3. 已发生的实证（可信、0 非法/0 forfeit）

| 口径 | 结果 |
|---|---|
| 零注入 battle 学习头（104 维，仅替换 battle；build/布局=产品）vs 冻结 hard31 dev n=600 | **+14.67pt**（p≈0） |
| 同头 mirror 直接对 2.2.2 n=600 | **+13.67pt**（p=0.0009），per-config **−72 ~ +100pt** |
| 同头 mirror 对 2.3.0（去注入版）n=300 | **+5.67pt（p=0.355，CI 含 0）** |
| 行为 | battle 中该头只做 **draw 229 / end_turn 225，0 次 place/flip/settle/move**；对局长度约 2× |
| 证据 | `tools/tmp-v28/pure2/REPORT.md`（sha `5B5EC977…`）、`screen/*.json`、`diag-actions.js` |

结论：**规则允许下，AI 会自然学出「囤牌拖决战」的局部最优**；对旧 heuristic（hard31/2.2.2）收益巨大，对 2.3.0 收益不显著但方向为正。这不是 AI 缺陷（它是规则内最优策略），而是**规则/数值设计空间**。

## 4. 可选改法（供设计决策；均需 Lead 改 engine + QA 全量回归）

| 方案 | 改动 | 预期效果 | 风险/代价 |
|---|---|---|---|
| **A 不改**（保持规则） | 无 | 保留「囤牌」作为合法策略；AI 可学，但产品 ML 友好度低、对局可能变慢 | 玩家可能觉得「拖」；AI 学习会浪费在 exploit 上 |
| **B 摸牌每回合限 1 次** | engine 回合内 draw 计数 + 合法性检查 | 直接打断「一回合连摸 2 次」式囤牌；4 区以下影响小 | 需要引擎状态字段（可加 `turnProgress.drawCount`，公开信息，不破坏公平）；规则文档/UI 提示同步 |
| **C 摸牌成本 2→3 AP** | ACTION_COSTS.draw 改 3 | 囤牌=整回合，节奏代价显著；改动最小 | 正常补牌也变贵，可能改变战役节奏；需要平衡测试 |
| **D 决战阈值提前（2X→3X）或决战补牌减少** | engine 阈值/补牌常数 | 压缩「囤牌窗口」，减少决战后手牌差 | 对局变短、结算变快；可能影响现有难度/随机性平衡 |
| **E 手牌上限（如 `2R+2`）** | 合法性/行动检查 | 直接封顶囤牌收益 | 上限需与初始手牌 2R 协调；摊牌手牌总和比较的方差变小 |
| **F 改摊牌平局比较项** | 例如比较「未结算区域数/翻牌数/剩余 AP」等 | 降低手牌囤积的终局收益 | 规则语义变化最大，玩家认知成本高 |

> 建议优先级（待用户定）：**C（成本 3AP）+ B（每回合 1 次）** 改动小、对现有系统语义扰动低；若想保节奏则 **D（阈值 3X）**；不建议 F（会改变玩法核心）。
